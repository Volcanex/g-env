# Codex in the G-System

The `G-System session context` comes from the neutral loader at
`~/.agents/session-context.py`, using `~/.agents/host.md`, the sources in
`~/.agents/context.json`, and Brain Pulse/orientation. No Claude install
is required. If the block is absent, before project work run:

```sh
python3 "$HOME/.agents/session-context.py"
```

Read the result once. If unavailable, report it and read context.json/source
files directly; use Brain pulse_page and brain_init when available. Sections are
whole; their pointers name reference to read only when this task needs it. HTTP
injection does not establish MCP connectivity; verify a tool call before claiming
Brain connected. Do not invent skill/server counts.

Use Codex's exposed tools and models; Claude agent names are not registrations.
Delegate narrow independent reconnaissance/research to Luna when available, with
bounded inputs, evidence requirements and fork_turns="none" where supported.
Keep architecture, ambiguity, visual judgment and final quality with a stronger
model. Routine work needs no team. Use isolated worktrees for concurrent writers.
The shared context owns execution, research, safety, memory and verification
rules. Shared skills live at `~/.agents/skills`; load only relevant ones.

Read nearest repository AGENTS instructions. Compatibility CLAUDE/AGENTS pairs
are reconciled by genv/scripts/mirror-claude.py; Codex itself need not expand
standalone Markdown imports because the neutral loader does that.

Hooks may need trust: inspect `/hooks`, and never claim injection without seeing
its content. Local Codex model/routing config does not configure hosted ChatGPT
Work. Tokens and API pricing do not determine subscription usage; use observed
quota/reset data and mark stale or unavailable data explicitly.

## Working with the operator

Carry the objective and agreed decisions through conversational steering. Answer
their actual question; discuss unresolved choices before acting on them. Own routine
execution and verification without repeated permission requests. Judge progress
by the result they can use, and change approach when a complaint repeats.

Example: a migration is not delivered until their sandbox runs the intended build
and preserves the agreed behavior; passing component tests is insufficient.
